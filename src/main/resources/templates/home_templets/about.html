SYSTEM DESIGN & ARCHITECTURE

ℹ️ Inside EventSync

EventSync is an advanced, real-time Full Stack Web Application that integrates modern software patterns to manage and schedule custom service packages.

The Technology Stack

MongoDB (NoSQL) Spring Boot 3.2 Thymeleaf Engine Bootstrap 4.6

Why MongoDB instead of SQL?

MongoDB stores event packages as **BSON documents** (NoSQL model). For event systems, this is highly superior because:

  • Schema Flexibility: Events can vary. A marriage package might have unique fields like 'Catering Menu', while a Tech Conference might have 'Speaker Profiles'. MongoDB handles this dynamic data effortlessly.
  • Embedded Arrays (Denormalization): Instead of complex SQL many-to-many join tables, we embed attendee IDs directly inside the Event document (`registeredUserIds`), resulting in **O(1) read operations**!

Thread-Safe Booking Engine

To protect against double-bookings and booking overselling, the backend utilizes a **synchronized service registration block**. Even if 100 concurrent clients try to book the last available wedding package, our engine handles bookings sequentially, ensuring available seats are decremented accurately.

Clean MVC Structure

Following strict Spring design patterns, the code is separated into isolated layers:

  • Entity Layer: Maps Java classes to MongoDB collections.
  • Repository Layer: Manages database queries using `MongoRepository`.
  • Service Layer: Holds atomic transactional logic.
  • Controller Layer: Separates UI views (`frontendcontrollers`) from REST services (`controller`).
